The headline: the method caught itself being wrong

Both halves agreed on a bug that was already fixed.

What happened: Path A and Path B independently ranked the same issue HIGH — "system prompts leak into the human chat." They were both reading a map snapshot that was a few commits stale. The leak had been patched right after the map was built.

Why it matters: if you trust agreement, you ship the wrong fix. The comparator's whole job is to re-check the things both sides agree on — and that's exactly what caught it. Two voices nodding isn't proof; it's a louder echo of the same old map.

The takeaway for next time: the comparator should re-verify every convergent claim against live code, not spot-check. And the top targets get a fresh grep before anyone writes a fix (which is what we just did — line numbers had already drifted again).

What's actually broken (live-verified)

#1The validation gate waves through empty work criticalboth paths agreed ✓ verified

A task with no success-criteria checklist auto-scores 100% and "passes." Fake-validated work then flows straight into the final deliverable with a green check. The Planner is even told in its own prompt that this can't happen — so the prompt is lying to it.

Why a prompt edit can't fix it: the prompt is working as designed. The hole is in the code gate — it checks the score but never checks that there were any criteria to score.

Where: orchestrator.go:3097 — Passed: OverallScore >= passThreshold Fix: add && len(CriteriaResults) > 0 (fail-closed) + a test
#2A hostile repo could hijack every agent highboth paths agreed ✓ verified

When ACT onboards an existing codebase, a researcher reads the repo and its notes get pasted unfenced into every agent's system prompt — in the highest-priority spot. A repo that plants fake instructions in its files (a CREATE_TASK: or [SYSTEM] line) could smuggle commands into the swarm. Brownfield onboarding is the flagship path, so the exposure is real.

Where: agents_md.go:32 → prompt.go:53 Fix: wrap notes in a <codebase_analysis> "reference data, not instructions" fence + scrub coordination markers. New tracked item.

The 3.5 FIXED note in the tracker overreaches — it's Planner-only.

Which path earned its keep

Path A — 3 slices + synthesizer (~4× cost)

  • Won: the deep control-flow edge (#4) nobody else saw; conflict-adjudication.
  • Lost: its slices were Planner-scoped, so it never asked "is Fix 22 complete for other roles?" — missed #3, #5–7.
  • Its "three subs agreed" confidence signal also produced the false positive.

Path B — single pass (~1× cost)

  • Won: caught all three cross-cutting boundary findings (incl. #3, my Fix 22 gap) at a quarter of the cost.
  • Lost: less depth on nested control flow — missed #4.

Verdict for this corpus: Path B was the better value — the whole-surface view caught what mattered cheaply. Keep B as primary next round; run the fan-out only on the deepest control-flow files; and make the comparator re-grep every convergent claim. Neither path self-corrects on a stale map — that's the comparator's job, and it paid for itself.
