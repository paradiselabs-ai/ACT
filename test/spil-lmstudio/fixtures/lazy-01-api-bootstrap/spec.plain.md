I need you to bootstrap a small REST API in this empty sandbox. It's a user-management service called users-api. The codebase will be extended later with authentication and a real database, so for now keep users in an in-memory Map keyed by user id, scoped inside the users router module. There's no persistence across process restarts — that's fine for this MVP, but the layout and conventions need to be clean enough that the auth and DB work later doesn't have to refactor the foundation.

Use Node.js (version 20 or newer) with Express 4 — the dependency should be express at ^4.18.0. The module system is CommonJS throughout — require and module.exports, no ESM, no .mjs files. For testing, we'll use vitest (^1.0.0) and supertest (^6.3.0) as devDependencies. The package.json needs three scripts: start runs node src/server.js, test runs vitest run, and dev runs node --watch src/server.js.

The Express app should live at src/server.js. It mounts a users router and a health router, calls express.json() middleware before mounting them, exports the app via module.exports (so tests can import it), and only calls app.listen() when require.main === module (so the supertest tests don't try to bind a real port). After all routers, add a catch-all handler that returns 404 with the JSON body { error: 'not found' }. Mount the routers at /users and /healthz respectively.

The two routers live under src/routes — users.js for /users and health.js for /healthz. Both export an Express Router via module.exports. The health router is trivial: a single GET handler at the root of its mount that returns 200 with { status: 'ok' }. No auth, no DB, this needs to always succeed because it'll get used as a liveness check eventually.

The users router is where the real work is. The in-memory storage is a Map keyed by user id at module scope. A User is { id, name, email, createdAt } where id is generated at create time using require('crypto').randomUUID() (no extra dependency needed), and createdAt is an ISO 8601 timestamp string. The router exposes three endpoints. GET / returns 200 with { users: User[] } — always an array, empty when no users have been created. GET /:id returns 200 with the User object directly (not wrapped in any envelope), or 404 with { error: 'user not found' } if no such id exists. POST / accepts { name, email } in the request body, validates that both fields are present and non-empty strings, rejects bad input with 400 + { error: 'name and email are required' }, and on success creates a User with a new id and current ISO createdAt, stores it in the Map, and returns 201 with the created User object directly.

Stylistically, write every handler as an async function — even the trivial ones that don't await anything — so the codebase has a uniform handler shape. Async/await throughout; no .then() chains, no callbacks. Each handler must return after sending its response so there's no risk of double-responding after res.json(). The router variables in each file are camelCase (usersRouter, healthRouter). Don't introduce a UserService or model layer — for this size of project the in-memory Map directly inside src/routes/users.js is the right call.

Tests go in tests/server.test.js. Use vitest's describe/it/expect (imported from 'vitest') and supertest's request (imported from 'supertest'). Import the app with const app = require('../src/server'). You don't need to start a real server — supertest's request(app) handles that for you, which is why server.js gates app.listen() on require.main === module. Cover at least five cases: GET /healthz returns 200 with status ok; GET /users initially returns an empty array; POST /users with a valid body creates a user and returns 201; POST /users with missing email returns 400; GET /users/:id with an unknown id returns 404.

You also need a .gitignore at the repo root with these entries on separate lines: node_modules, dist, .env, coverage.

And a README.md at the repo root, starting with the heading "# users-api". One short paragraph describing what this is and noting it's an in-memory MVP. Then three sections — Quickstart (npm install + npm start + the resulting localhost URL), Endpoints (a bulleted list of the four routes with method + path + brief purpose), and Testing (how to run npm test).

Important: this is a static bootstrap. Don't invoke npm install, vitest, or any external process — the test will only check file contents and structure. All file paths are relative to the sandbox root.

To consider this done, every one of these must be true: package.json exists at the root and parses as valid JSON with scripts.start = "node src/server.js", scripts.test = "vitest run", scripts.dev = "node --watch src/server.js", and dependencies.express plus devDependencies.vitest plus devDependencies.supertest all present; .gitignore exists with all four entries on separate lines; src/server.js exists and requires express, mounts /healthz and /users, exports the app, and gates app.listen() on require.main === module; src/routes/users.js exists, defines GET, GET :id, and POST handlers, exports a Router; src/routes/health.js exists, defines GET returning { status: 'ok' }, exports a Router; tests/server.test.js exists, imports app from ../src/server, uses supertest's request(app), and has at least five it() calls; README.md exists with the "# users-api" heading and contains the strings Quickstart, Endpoints, and Testing as section markers.
